# ADR 0004：S3 有限画布与布局缩放

## 最新修订：只缩放视图与双模式

宿主可达修订：独立Host采用Show而非ShowDialog，去除Owner=this，允许主窗进入前台而非始终被owned宿主覆盖；新增显式返回主窗按钮，不通过最小化/销毁宿主实现返回。关闭仍依赖MainWindow._hosts逐一解除及失败阻止退出，不能依赖自动owner关闭。受控UI验证owner为NULL、返回主窗前台/宿主不最小化及安全恢复通过；最终S3仍须同画布原生模式，不把此过渡修复当完成。

用户本轮明确要求画布缩放不得改变原生尺寸，替代下方历史“缩放容器并重新排版”的方案。经源码核查与Microsoft Technology Regions Overview，HwndHost中的HWND不受WPF仿射缩放，WPF覆盖原生airspace也有限制。现有ResizeNative将目标填满宿主，LocationChanged亦强制Resize，不能直接用作新双向同步。

用户已选择同一画布“布局总览 + 原生1:1交互”双模式：总览矩形仅表达真实几何，不显示截图/模拟内容；原生模式未来显示真实HWND和邻窗可点击边带，共享布局。视图变换不改原生尺寸，明确调整窗口大小才同步原生；布局仅内存保存，不扩展S4。

本次只实现首段总览：WindowOverviewModel按snapshot.Bounds * 96 / DPI读取原始比例，保留会话布局；CanvasView显示真实会话几何矩形并拖动/吸附，Zoom仅缩放WPF总览。SnapEngine严格小于12 DIP，边缘/相邻/等间距候选按距离、目标Guid与候选顺序稳定决胜。当前不支持任意较小/超出4096的原始几何，明确不纳入总览而非改原生或伪造尺寸。

尚未实现同画布原生模式、名称映射、调整大小/双向同步、边带/动画与鼠标完整验收；不宣称本次达到完整任务。原生模式须拆开宿主可见裁剪与目标实际尺寸，持久保留宿主；不能缩小HwndHost后调用旧ResizeNative冒充完整内容缩放。

## 总览名称与原始尺寸范围（2026-10-26 新电脑检查点）

总览卡片名称采用App层运行期映射，不修改Domain WindowIdentity：嵌入确认时从发现列表记录标题（空则进程名），按Hwnd与会话关联，会话失效即清理；仅内存显示、不持久化、不写日志，不是持久化身份。较小（低于240×160 DIP换算）或超出4096×4096画布的原始几何仍不纳入布局，但改为逐项省略清单（原始物理px、DPI、换算DIP与原因），在总览状态区明确展示，不以单条提示静默隐藏，也不伪造几何或修改原生。用户已人工验证总览名称/原始尺寸行通过。未改变本ADR其余决策；同画布原生模式与完整尺寸调整仍待后续子任务。

## S3收尾决策：外部尺寸读回与Z序突出（2026-10-27）

外部尺寸读回：显式放置（画布）会话在LocationChanged事件读回目标当前宿主相对bounds（GetWindowRect+ScreenToClient），与最近显式放置值比较——±2px内视为自身放置的回声而忽略（防反馈循环），显著差异记录为ExternalBounds，由画布在会话刷新时按DPI换算同步容器逻辑尺寸；后续显式放置覆盖待同步读回值。未显式放置的S2会话保持"宿主移动即填满"的既有已验收语义，引擎以会话是否经过Place区分，不改变公共状态机。

非全屏突出：不缩放、不挪窗、不重建会话——各宿主表面按布局ZIndex升序SetWindowPos置顶（NOACTIVATE），选中容器的宿主位于兄弟最上；邻窗未被覆盖的边缘保持原生可点击。切换为纯Z序变化即平滑，不破坏保存的布局关系。S3以用户2026-10-27"以记录代替人工验收"授权退出；人工场景豁免如实记录，不伪称通过。

## T0702b 同画布原生1:1模式（2026-10-26）

新嵌入入口"嵌入到画布(1:1)"直接在空间画布承载面内嵌入真实HWND；S2独立宿主路径不变。裁剪为原生方案：宿主HWND尺寸=可见裁剪区域物理px（由NativeGeometry.Project计算），目标SetBounds为负偏移+完整原始物理尺寸，超出宿主客户区的部分被Windows原生裁剪——HwndHost不受WPF裁剪（airspace），不以缩小宿主冒充内容缩放。视图zoom/pan仅更新宿主位置与裁剪，目标实际尺寸不变；仅显式尺寸调整（T0802）可改变它。新会话绑定即发送全尺寸Place，随后在原生模式下按投影放置；会话失效清理宿主，主窗关闭逐画布会话安全解除，失败保留宿主与快照。引擎PlaceAsync为显式边界操作，走既有专用STA串行派发，与旧ResizeNative（S2填充语义）并存且不用于画布模式。

## T0702a 原生1:1几何投影（2026-10-26）

Domain新增NativeGeometry纯投影：DIP与目标捕获DPI物理px往返换算；Project输出NativePlacement——目标实际物理尺寸（仅显式尺寸调整可变）与可见宿主裁剪面/裁剪偏移（由ClipRegion决定）严格分离，视口zoom/pan只改变裁剪、永不缩放目标。CanvasViewModel新增VisibleRegion()提供可见逻辑DIP区域。旧ResizeNative/LocationChanged填满宿主行为属S2已验收路径，保持不变；原生1:1宿主放置将在后续子任务消费该投影，不把缩小宿主或截图当内容缩放。

## 已确认决策

- 用户确认采用正坐标有限画布：4096×4096 DIP，容器限制在边界内，允许重叠；平移只改变视口，提供回到原点入口。
- 用户确认布局缩放并重新排版：50%–200% 时布局位置/容器尺寸缩放，后续真实 HWND 客户区随之改变，由目标应用重新排版，不保证像素/字体等比例缩放。
- T0701 空画布采用工具栏每次 10 个百分点调节，端点禁用，非法非有限值拒绝；滚动条和仅限空画布的中键捕获用于平移，不注册全局输入钩子。
- 现有发现 UI 作为默认页保留；画布为独立标签页。S2 独立 NativeHostingWindow 和安全恢复链不变，不以虚构窗口卡片代替原生承载。

## 当前实现与边界

CanvasViewModel 存储缩放和视口显示 DIP 偏移；逻辑原点为 offset / zoom，缩放时尽量保持原点，触及边界时夹紧。CanvasView 的 ScrollViewer 负责可达范围，背景 RenderTransform 只缩放当前 WPF 空画布元素，不声称能缩放 HwndHost。

T0702 后续必须将布局结果换算成实际宿主位置/客户区，处理裁剪、DPI、最小尺寸和原生 airspace；不能直接把此 RenderTransform 套在真实 HWND 上宣称完成。恢复失败须继续保留宿主及会话快照。

容器模型、选择/层级、拖动与缩放、固定容器语义、磁吸冲突与最小化语义未实现；相应子任务前确认剩余 Q04/Q05。当前没有 JSON schema 或工作区变化。

## T0901 非固定纯布局检查点

用户随后确认空画布验证完成并授权下个子任务。本次仅新增纯Domain布局，不接UI、原生或JSON：

- ContainerLayout仅含Guid、逻辑DIP几何和层级，不含HWND/持久化身份；CanvasLayout防御复制集合并提供只读快照。
- 基于已确认有限边界，最小240×160 DIP，允许重叠；非有限/负坐标/越界拒绝，失败保留原布局，不静默夹紧。UI拖动边缘的具体限制交互留到后续。
- 唯一非空Guid及非负唯一ZIndex是当前运行期布局不变量；移动/尺寸不更改其他容器。前后层级按原ZIndex保留其他容器相对顺序，并紧凑重排避免溢出；输入集合顺序不改变，重复端点操作幂等。
- 固定容器语义不定案，本次模型不引入IsPinned。固定、磁吸和最小化仍在相应子任务前确认；不冻结S4 schema或扩展已有公共接口。

## 固定策略与真实会话选择

后续用户明确选择“锁位置和尺寸”。ContainerLayout的IsPinned为init属性，默认false；SetPinned只改锁状态，移动/尺寸变化在固定时拒绝并保留原快照，相同几何幂等成功，解锁恢复编辑。固定不阻止层级、选择、应用输入或安全解除，也不锁画布视口。此规则仅布局层生效，不冻结JSON schema，不宣称已限制S2独立宿主的系统拖动/尺寸。

选择入口以真实活动/待恢复EmbeddingSessionStatus为数据源，SessionId作为选择身份，终态/失效刷新清除，DetachFailed仍可选择；不自动切换到其他会话。主窗显式刷新，不增加全桌面轮询；定位前重新查询并按HostSurface匹配现存宿主。关闭等待正在执行的会话查询，失败不直接解除或销毁宿主。

新增会话页不是画布内容器；T0702/T0801仍需真实卡片、客户区/DPI联动和固定UI。最终非原生89项与受控双宿主选择UI Smoke复测通过；S3未退出。
